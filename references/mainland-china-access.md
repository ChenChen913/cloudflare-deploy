# 中国大陆访问风险

核实日期：2026-11-20。默认域名的可达性会随网络、时间和政策变化；本文是决策提示，不是可用性保证。

## 1. 证据标注

| 标注 | 含义 |
|---|---|
| 官方 | 平台文档或定价页明确写出的规则；只能证明平台声明，不能证明中国大陆实际可达性 |
| 网络观测 | 社区、用户或外部探测的反馈；没有日期、地区、运营商和原始结果时只能算线索 |
| 实测 | 本仓库保存了日期、地区、运营商、DNS / TCP / TLS / HTTP 结果和探测来源 |
| 待验证 | 没有可复现证据，或平台没有承诺 |

**本仓库目前没有保存中国大陆实测数据。** 下文关于 DNS 污染、访问不稳定、默认域名不可达的描述属于网络观测或待验证，不是平台官方声明，也不是本仓库的实测结论。

## 3. 硬提示（目标用户含大陆或未明确时必须输出）

只要目标用户地域包含中国大陆，或用户未明确说“只面向海外”，选型结果必须附带以下提示，不得折叠、省略或只放到报告末尾。以下是网络观测结论，不是平台官方声明；本仓库没有保存大陆实测数据：

- Vercel 的 `*.vercel.app` 默认域名在中国大陆被反馈为 DNS 污染，直接访问通常超时；绑定自定义域名可能改善，但 Vercel 官方明确不保证中国大陆的可用性或性能。
- GitHub Pages 的 `*.github.io` 在中国大陆被反馈为访问不稳定，部分网络环境不可达。
- Netlify 的 `*.netlify.app` 同样常被反馈为无法直接访问。
- Cloudflare Pages / Workers 的 `*.pages.dev` / `*.workers.dev` 通常被反馈为可达性更好，但也不是中国大陆合规托管。
- 换自定义域名只能缓解，不能保证稳定；稳定大陆访问需要 ICP 备案 + 国内云 / CDN。

## 4. 两条路线

### 路线 A：海外托管 + 自定义域名

适合：主要用户仍在海外，或大陆用户只是少量、可以接受偶尔不可用。

做法：

1. 选一个默认域名风险相对低的平台，Cloudflare Pages 通常比 Vercel / GitHub Pages / Netlify 默认域名更稳。
2. 绑定自定义域名，启用 HTTPS。
3. 把关键静态资源自托管，减少对 Google Fonts、第三方 CDN、境外统计脚本的依赖。
4. 准备降级方案：关键页面有镜像或备用入口；监控大陆用户的可达性反馈。

必须承认的代价：

- 仍可能被限速、阻断或出现高延迟。
- 自定义域名只缓解默认域名被污染的问题，不改变海外托管在中国大陆的不确定性。
- 不能承诺 SLA。

### 路线 B：ICP 备案 + 国内云 / CDN

适合：大陆用户为主，或业务依赖稳定的大陆访问。

做法：

1. 购买国内云服务器、对象存储或静态托管。
2. 完成 ICP 备案；域名解析到国内云 / CDN。
3. 按国内云的要求做实名、内容合规和安全组配置。
4. 海外用户如果也需要访问，可以保留海外站，或使用 CDN 的多区域能力。

代价：

- 备案需要时间和材料。
- 国内云有实名、内容审核和合规要求。
- 迁移成本和运维责任高于海外静态托管。

## 5. 怎么验证，而不是猜

只读检查，不修改 DNS：

```powershell
# Windows：看解析和状态码（把 URL 换成实际地址）
Resolve-DnsName example.com -Type A
curl.exe -sS -o NUL -w "%{http_code} %{time_total}s`n" https://example.com/
```

```bash
# macOS / Linux
dig +short example.com
curl -sS -o /dev/null -w "%{http_code} %{time_total}s\n" https://example.com/
```

更可靠的验证方式：

- 让真实的大陆用户在电信、联通、移动网络各测一次。
- 用多个第三方探测点，记录时间、地区、运营商、状态码和耗时。
- 观察 Search Console / 统计里的地区流量和错误率。
- 不要用一次 `curl` 200 代表“大陆稳定可用”。

### 实测记录模板

如果要做实测，至少记录以下字段；没有这些字段的结论只能标“网络观测”或“待验证”：

| 字段 | 示例 |
|---|---|
| 日期 / 时间 | 2026-11-20 20:00 CST |
| 地区 / 城市 | 上海 |
| 运营商 | 电信 / 联通 / 移动 |
| 探测来源 | 真实用户、第三方探测点、CI 节点 |
| DNS | A / AAAA / CNAME 结果，是否被污染 |
| TCP / TLS | 是否连接成功、证书是否有效 |
| HTTP | 状态码、TTFB、是否被重置 |
| 自定义域名 | 域名和绑定方式 |
| 结论 | 可达 / 不稳定 / 不可达 / 待复测 |

不要在仓库里伪造实测数据；没有记录就写“未验证”。

## 6. 报告写法

目标用户含大陆时，报告单独用一节“中国大陆访问风险与建议”，至少包含：

1. 默认域名风险：点名 Vercel / GitHub Pages / Netlify / Cloudflare Pages。
2. 是否绑定自定义域名，绑定了哪个域名。
3. 选择路线 A 还是路线 B，以及理由。
4. 已验证的内容和未验证的内容。
5. 不承诺“稳定大陆访问”，除非已经走备案 + 国内云并有实测证据。
